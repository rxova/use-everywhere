# Working on this repo as an agent

`use-everywhere`: state, messages, presence and leader election that exist in every tab, window and
worker on an origin, with a React API. Four published packages plus the docs site.

[`CONTRIBUTING.md`](CONTRIBUTING.md) is the reference and stays the source of truth: the
[architecture](CONTRIBUTING.md#architecture-overview), [setup](CONTRIBUTING.md#install--common-commands),
[the quality gates](CONTRIBUTING.md#quality-gates), [the release process](CONTRIBUTING.md#branching--releases).
Read it. This file only covers what an agent gets wrong, which is a different and much shorter list.

## Five things to know before editing

| Path                              | What it actually is                                                                                       |
| --------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `packages/core/src/`              | The engine. Protocol, transports, clocks. One class per file; types in sibling `*.types.ts`.              |
| `packages/react/src/`             | The hooks, layered on core. Re-exports a curated core surface; Inspector ships on the `devtools` subpath. |
| `apps/docs/src/content/docs/api/` | **Generated by TypeDoc at build time and gitignored.** Never edit. Edit the TSDoc in the source.          |
| `apps/docs/src/content/docs/**`   | Hand-written prose. Yours to edit.                                                                        |
| `packages/*/llms.txt`             | Hand-written, ships in the tarball, read by agents out of `node_modules`. See below.                      |
| `packages/tooling/`               | Private tooling — the release gate and the check scripts. Never published, never imported by a package.   |

## The gate

```bash
pnpm verify     # what pre-push runs, in CI's order — run this before you claim done
```

Scope while iterating: `pnpm --filter @use-everywhere/core test`.

**`pnpm verify` deliberately does not build the docs site.** `rehype-mermaid` renders the two
diagrams through headless chromium, so building it needs `pnpm --filter @use-everywhere/docs exec
playwright install chromium` first, and gating every push on that would make a fresh clone fail for a
reason unrelated to the change. The Docs workflow owns that build. If you touched `apps/docs`, run it
yourself:

```bash
pnpm --filter @use-everywhere/docs build     # includes check-md-routes.mjs
```

## Invariants, and what enforces them

Each of these has caught a real regression. The right-hand column is why you cannot "just try it and
see" — several are enforced late, so breaking one is cheap to do and expensive to discover.

| Invariant                                                                                                                                                                | Enforced by                                     |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| **Zero runtime dependencies in core.** No peers at all; `react >= 18` only for the React package.                                                                        | review + `pnpm size` budgets                    |
| **95% coverage per file** — a thinly-tested new file fails even when the repo average is fine.                                                                           | `pnpm test`                                     |
| **Every `devWarn` carries a permanent `UEnnnn` code and a literal `NODE_ENV` guard.** A retired code is never reused: an old build in somebody's browser still emits it. | `error-codes.test.ts`, `dev-stripping.test.ts`  |
| **Every `UEnnnn` has an entry in `errors.md`, and every entry has a live code.**                                                                                         | `error-codes.test.ts`                           |
| **Every published package ships an `llms.txt`, in `files`, documenting only exports that exist.**                                                                        | `check-llms.ts`, `pack:smoke`                   |
| **Every docs page has a `.md` twin containing no unhandled markup and no dangling links.**                                                                               | `check-md-routes.mjs`, in the docs build        |
| **A changeset for anything user-facing.**                                                                                                                                | `check-changeset.ts` in CI                      |
| **Conventional Commits.**                                                                                                                                                | commitlint, on both the commit and the PR title |

### jsdom is never the layer for real cross-tab behaviour

jsdom has no `BroadcastChannel` worth the name and no second tab. An assertion there about
convergence, presence pruning or leader handover only re-reads the object the test just wrote — it
passes whether or not the library works. Use `@use-everywhere/test-utils` (`createScenario`) for
multi-tab logic in-process, and the Playwright suite in `e2e/` for anything that needs a real browser.
This is the single most common way to add a test that proves nothing.

**Delivery is asynchronous, in the scenario harness as in a browser.** Assert after
`await scenario.settle()`, never on the line after the write. Hydrating a late joiner costs up to the
jittered snapshot delay, so a newly-opened tab needs `settle(80)`, not a bare `tick()`.

## The agent-facing surfaces

This repo is set up to be read by coding agents, and those surfaces drift silently if you do not know
they exist. There are four, and three are generated:

| Surface                       | Where                   | Generated? |
| ----------------------------- | ----------------------- | ---------- |
| Raw-markdown twins, 257 pages | any docs URL + `.md`    | yes        |
| `llms.txt` — the index        | site root               | yes        |
| `llms-full.txt` — everything  | site root               | yes        |
| `packages/*/llms.txt`         | inside each npm tarball | **no**     |

The three generated ones all come from `docsPages()` in `apps/docs/src/lib/docs-md.mjs`, so they
cannot disagree about what pages exist. **Fix the normalizer, not the output.**

**Two rules when touching `apps/docs/src/lib/`:**

1. **Never apply a rule across a whole document.** Almost every `import` line in these docs is inside
   a code fence — they are the illustrative snippets. Everything goes through `mapUnfenced`.
   `check-md-routes.mjs` shares the same fence splitting, so the checker and the normalizer cannot
   disagree about where a fence begins.
2. **`llms.txt` is an index and must stay one.** There are 209 generated reference pages against 46
   of prose. `## Optional` links the three TypeDoc index pages, not the 209 — see `optionalLinks` in
   `llms.mjs`. A 24 kB budget in `check-md-routes.mjs` is what stops that regressing.

`packages/*/llms.txt` is the one you edit by hand. It is what an agent reads out of `node_modules`
after an install, so its failure mode is quiet: a renamed export leaves the file describing an API
that no longer exists and every test still passes. `check-llms.ts` checks the `## API` table against
the package's real entry points (`src/index.ts` plus each `src/*/index.ts`), so **rename an export and
update the table in the same commit.**

## Change these together

A behaviour change touches several surfaces, and shipping fewer than all of them ships an invisible fix:

- the code, plus tests at the right layer (see the jsdom note above)
- the TSDoc — it **is** the published API reference, via TypeDoc
- the prose page under `apps/docs/src/content/docs/`
- `packages/<pkg>/llms.txt`, if the change is to the public surface
- `errors.md`, if you added or retired a `UEnnnn`
- a changeset

## Traps already hit, so they are not hit again

- **Doc-relative links do not resolve on their own.** These docs came from Docusaurus and write links
  as `../core/transports.md`. Astro emits them verbatim, and `starlightLinksValidator` is configured
  with `errorOnRelativeLinks: false`, so nothing checked them — 235 were shipping as dead links.
  `resolveRelativeLinks` now turns them into absolute twin URLs, and `check-md-routes.mjs` fails on
  any that do not land on a real twin. Both spellings work; neither is checked by the link validator.
- **Astro ids are lowercased.** TypeDoc writes `README.md` and Starlight serves it at
  `/api/core/readme/`. A link written with the true filename resolves to a twin that does not exist.
- **`index.md` has the id `index`, not `''`.** Assuming the empty string puts `source: /index/` — a
  route this site does not serve — into all 257 twins, and nothing else notices.
- **`playground/` is not a content page.** It is a standalone React app compiled into `public/`, so
  Astro copies its HTML into `dist` with no markdown behind it. It is excluded in `check-md-routes.mjs`.
- **The docs build needs the libraries built first.** TypeDoc resolves `use-everywhere` → core through
  `dist` types, and the playground imports the package by name. Run `pnpm run libs:build` first, or
  let Turbo do it.
- **The pre-push hook runs the full `pnpm verify`** (minutes). Use `--no-verify` for docs-only pushes,
  and run the gate deliberately.
