## Summary

One paragraph. If it needs two, the change may be two changes.

## Motivation

What is wrong today, stated as something a user hits rather than something a
maintainer dislikes. A real example beats a principle.

## Proposal

The change, precisely enough that someone else could implement it. Include the
signatures.

## What breaks

The list of code that stops working. Not "this is backwards compatible" — write
the code that breaks, or write "nothing, and here is why".

How does someone find out? A type error is kind. A runtime error with a code is
acceptable. Silence is not.

## Migration

Mechanical or not. If mechanical, can a codemod do it? If not, what does the
person have to decide, and what does the deprecation warning tell them?

## Alternatives

Including the one where we do nothing. Say what that costs — sometimes it costs
very little, and that is a finding rather than a failure.

## Unresolved questions

What this RFC deliberately does not settle.
